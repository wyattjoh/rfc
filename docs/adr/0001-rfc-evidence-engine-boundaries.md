# RFC evidence engine boundaries

**Status:** accepted

The RFC research product is split into `@wyattjoh/rfc-core`, `@wyattjoh/rfc`, and `@wyattjoh/rfc-pi` Bun workspaces. The Pi package publishes the native extension and shared lookup skill while invoking the CLI through `bunx`; it does not duplicate the evidence engine or credential boundary. The core exposes a Promise-based facade backed by one managed Effect runtime; its consumer-facing methods return plain data and Promises while its request-local discovery, filesystem, path, source-cache, and DecisionModel services remain replaceable Effect layers. The CLI is the composition root: it validates typed non-secret defaults, resolves the TypeSafe API key lazily through one injectable `Bun.secrets` credential boundary, and passes provider options into the core without letting the core read environment variables or operating-system credential stores. The core constructs the official `@effect/ai-typesafe` DecisionModel layer from those explicit options. Candidate discovery and source retrieval are deterministic and bounded before any semantic judgment; the core ranks RFCs and selects exact passages but leaves reasoning and answer composition to the caller (see [ADR 0005](./0005-jev-ranked-retrieval-without-research-statuses.md)), and operational failures surface as versioned typed errors. Authentication commands expose only safe credential metadata, while masked prompts and explicit standard-input mode keep key values out of argv, logs, and JSON. This boundary avoids legacy Raycast coupling while preserving provider, storage, policy, and credential replaceability.
