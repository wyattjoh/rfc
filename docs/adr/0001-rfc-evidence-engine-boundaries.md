# RFC evidence engine boundaries

**Status:** accepted

The RFC research product is split into private `@wyattjoh/rfc-core` and `@wyattjoh/rfc` Bun workspaces. The core exposes a Promise-based facade backed by one managed Effect runtime; its consumer-facing methods return plain data and Promises while its request-local discovery, filesystem, path, source-cache, and DecisionModel services remain replaceable Effect layers. The CLI is the composition root: it validates typed non-secret defaults, resolves the TypeSafe API key lazily through one injectable `Bun.secrets` credential boundary, and passes provider options into the core without letting the core read environment variables or operating-system credential stores. The core constructs the official `@effect/ai-typesafe` DecisionModel layer from those explicit options. Retrieval remains deterministic and bounded before semantic judgments, and uncertain or unsupported evidence fails closed through explicit versioned statuses and typed errors. Authentication commands expose only safe credential metadata, while masked prompts and explicit standard-input mode keep key values out of argv, logs, and JSON. This boundary avoids legacy Raycast coupling while preserving provider, storage, policy, and credential replaceability.
